## 1. System Overview & Core Objective
The **Lucky Lotto Information System (LLIS)** is a modern, responsive web application and background microservice engineered to modernize the legacy VB.NET 2013 / MySQL desktop lotto application into a high-performance web platform with offline resilience.

### Strictly Supported PCSO 6-Number Lotto Games
The system strictly supports the **five official PCSO 6-number lotto games**:
1. **Ultra Lotto 6/58** (Numbers: 1–58, Exactly 6 unique numbers) — Drawn Tue, Fri, Sun
2. **Grand Lotto 6/55** (Numbers: 1–55, Exactly 6 unique numbers) — Drawn Mon, Wed, Sat
3. **Super Lotto 6/49** (Numbers: 1–49, Exactly 6 unique numbers) — Drawn Tue, Thu, Sun
4. **Mega Lotto 6/45** (Numbers: 1–45, Exactly 6 unique numbers) — Drawn Mon, Wed, Fri
5. **Lotto 6/42** (Numbers: 1–42, Exactly 6 unique numbers) — Drawn Tue, Thu, Sat

*(Note: 6D, 4D, 3D Swertres, 2D EZ2, STL, and other non-6-number games are intentionally excluded to maintain strict statistical integrity for 6-ball matrixes).*

## 3. Official PCSO Draw Schedule & Automated Post-Draw Scraper
All official PCSO 6-number lotto draws occur at **9:00 PM PHT** (Philippine Standard Time, UTC+8).  
LLIS includes an intelligent automated post-draw scraper that triggers specifically according to the active game schedule of the day:

| Day of Week | Official Scheduled Games | Draw Time | Automated Scraping Schedule |
| :--- | :--- | :--- | :--- |
| **Sunday** | Ultra Lotto 6/58, Super Lotto 6/49 | 9:00 PM PHT | 9:30 PM & 10:15 PM PHT |
| **Monday** | Grand Lotto 6/55, Mega Lotto 6/45 | 9:00 PM PHT | 9:30 PM & 10:15 PM PHT |
| **Tuesday** | Ultra Lotto 6/58, Super Lotto 6/49, Lotto 6/42 | 9:00 PM PHT | 9:30 PM & 10:15 PM PHT |
| **Wednesday** | Grand Lotto 6/55, Mega Lotto 6/45 | 9:00 PM PHT | 9:30 PM & 10:15 PM PHT |
| **Thursday** | Super Lotto 6/49, Lotto 6/42 | 9:00 PM PHT | 9:30 PM & 10:15 PM PHT |
| **Friday** | Ultra Lotto 6/58, Mega Lotto 6/45 | 9:00 PM PHT | 9:30 PM & 10:15 PM PHT |
| **Saturday** | Grand Lotto 6/55, Lotto 6/42 | 9:00 PM PHT | 9:30 PM & 10:15 PM PHT |

### Admin Console Auto-Scrape Toggle
Administrators can enable or pause the automated post-draw scraping schedule at any time via the **Admin Console -> Sync PCSO** tab with the on/off switch. The toggle state is persistently saved in SQLite `system_config`.

## 3. Architecture & Project Structure
The frontend strictly adheres to **Clean Architecture** and the **Repository Pattern**:

```text
lib/
├── core/
│   ├── config/           # ApiConstants (local & cloud URL auto-resolution)
│   ├── constants/        # LottoConstants (game rules, limits, disclaimers)
│   ├── database/         # DatabaseExecutor, SQLite/WASM abstraction & seeder
│   ├── security/         # PasswordHasher (SHA-256 + secret salt)
│   ├── services/         # TextToSpeechService (browser Web Speech API)
│   ├── storage/          # WebSessionStorage (persistent token & backend URL)
│   └── theme/            # AppTheme (responsive material design with PCSO colorways)
├── features/
│   ├── authentication/   # AuthService, UserRepository, Login & Registration
│   ├── dashboard/        # Client & Administrator responsive consoles
│   ├── lotto_results/    # LottoResultRepository, official draw directory & filters
│   ├── lucky_pick/       # LuckyPickService, generator, saved picks & automated matching
│   ├── analytics/        # 1-year historical analytics engine (heatmaps, pairs, streaks)
│   ├── predictions/      # Statistical suggestion engine (for entertainment only)
│   ├── synchronization/  # PCSO scraper, parser, deduplicator & live terminal stream
│   ├── notifications/    # In-app match notifications & winning alerts
│   ├── users/            # Administrator user directory & activation controls
│   ├── settings/         # Security settings & backend cloud service URL config
│   └── migration/        # Legacy VB.NET MySQL to SQLite importer
├── shared/
│   ├── models/           # Domain entities (User, LottoResult, LuckyPick, etc.)
│   └── widgets/          # LottoBall (3D gradient), Responsive Cards, Disclaimer Banners
└── main.dart             # Application root with MultiProvider injection
```

## 4. Deploying the Backend Service (Render / Free 24/7 Cloud)

The backend microservice is located in `backend_sync_service/` and contains the SQLite central database, REST APIs, live logs SSE stream, and the automated post-draw cron scheduler.

### Option A: Deploy on Render (Recommended)
1. Fork or push this repository to your GitHub account: `https://github.com/kje999/llis`.
2. Sign up / Log in to [Render.com](https://render.com).
3. Click **New +** -> **Web Service** -> Connect your `llis` repository.
4. Fill in the service settings:
   - **Name:** `llis-backend`
   - **Root Directory:** `backend_sync_service`
   - **Environment:** `Node`
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Plan:** Free
5. Click **Create Web Service**. Render will build and launch your backend with a public HTTPS URL (e.g. `https://llis-backend.onrender.com`).
6. In the **Admin Console -> Settings** tab of LLIS, enter your Render URL into the **Backend Service Base URL** field and click **Save URL**.

#### Keeping Render Free Tier Awake 24/7:
Render's free tier sleeps after 15 minutes of inactivity. To keep the post-draw cron active 24/7:
1. Sign up for a free monitor on [cron-job.org](https://cron-job.org) or [UptimeRobot.com](https://uptimerobot.com).
2. Create an HTTP GET monitor pointing to: `https://your-service.onrender.com/api/health`
3. Set the interval to every **10 minutes**. This prevents your instance from sleeping and ensures the 9:30 PM & 10:15 PM post-draw scrapers fire reliably every day!

### Option B: Deploy with Docker / Fly.io / Koyeb
A `Dockerfile` is included in `backend_sync_service/Dockerfile`.
```bash
docker build -t llis-backend backend_sync_service/
docker run -p 8081:8081 llis-backend
```

## 6. Running Locally with 1-Click Batch Files

For local development on Windows:
1. **Full System Launcher (Both Web App & Backend Microservice):**
   - Double-click **`run_llis_full_system.bat`** in the project root.
   - Starts the backend on port `8081` and serves Flutter Web on port `8080`.

2. **Central Backend & SQLite Services Only:**
   - Double-click **`run_backend_sync.bat`**.

3. **Stop All Active Services:**
   - Double-click **`stop_all_services.bat`**.
   - Cleanly closes background tasks on ports 8080 and 8081.

4. **Rebuild Flutter Web:**
   - Double-click **`build_web.bat`**.
